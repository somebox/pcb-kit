# How a hardware project is laid out and documented

What the existing projects converged on (dodeca-v2-hardware, rp2354-messages-sign, siebenuhr controller-v2,
rgb-spotlight), written down so new ones start the same way. `templates/project/` has the skeleton.

## Layout

```
README.md            index: what the project is, where things are, naming of versions
DESIGN.md            requirements, decisions (dated, numbered), block designs, what the last version taught
LAYOUT.md            the PCB: floor plan, stackup and rules, scripted copper, routing, checks, silkscreen
PRODUCTION.md        how to order: order files, checklist (polarity, rotations), dated costs and quotes
BOM.md               from bomi
boards/<name>/       one KiCad project per board (<name>.kicad_pro/.kicad_sch/.kicad_pcb, fp-lib-table)
lib/                 the project's own symbols (<project>.kicad_sym), footprints (.pretty), 3dmodels/
scripts/             the project's generators and checks; they call pcbkit for the shared parts
design/              block definitions (JSON) when the schematic is generated
docs/previews/<board>/   generated by `pcbkit previews`: schematic.pdf, pcb-front/back.png, assembly-back.png, board.pdf, renders
docs/datasheets/     bomi datasheet summaries (markdown), the PDFs where licensing allows
build/               fab files and panels, git-ignored, regenerated before each order
archive/             earlier versions, kept whole
```

## Writing

- The first line under a document's title is its **status with a date**: what is done, what is next.
- Decisions are **dated and numbered** (D1, D2, ...) in DESIGN.md and never silently rewritten; a reversal is a new
  entry that names the old one.
- Positions are in board coordinates, millimetres, top view; say which side a part is on.
- Every generated artefact says what made it (`pcbkit previews`, `scripts/make_fab.sh`) so it can be regenerated.
- The order checklist in PRODUCTION.md is the list of things that went wrong before (polarity, rotation, BOM matching
  by value), each with the fix.

## Checks before an order

1. `pcbkit erc` clean, the project's netlist assertions pass.
2. `pcbkit drc --save` with 0 errors, 0 unconnected, 0 parity issues; warnings explained in LAYOUT.md.
3. `pcbkit check` with nothing unexplained; `pcbkit cleanup --dry-run` reports nothing.
4. A second opinion from KiCadRoutingTools' checkers (`check_drc.py`, `check_weird.py`, `check_connected.py`) on a
   copy of the board, for via-in-paste, stacked copper and near-open joints.
5. `pcbkit previews` regenerated and looked at: assembly map, silkscreen, plane coverage.
6. `pcbkit fab` (and `pcbkit panel` for panels); BOM reviewed against bomi for stock and extended-part fees.

## Scripting rules

- Scripts that touch `pcbnew` run under KiCad's Python and stay 3.9-compatible.
- Once a board is routed, never regenerate it from scratch: update incrementally and keep UUIDs.
- Lock copper that was placed deliberately (power necks, stitching vias); autorouters and cleanups leave locked
  items alone.
- A `.kicad_dru` syntax error silently disables every custom rule; run DRC after each edit of it.
- `BOARD.Remove()` on tracks and `FOOTPRINT.Remove(field)` corrupt the pcbnew bindings mid-run: edit the file text
  by uuid instead, in a fresh process.
