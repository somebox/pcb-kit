# pcb-kit

`pcbkit` is installed as a CLI (`uv tool install -e ~/src/pcb-kit`). `pcbkit --help` lists the commands,
`pcbkit <cmd> --help` the flags. Commands that need pcbnew re-run themselves under KiCad's Python; you never choose
the interpreter. pcbkit runs kicad-cli from a background copy, so it shows no dock icon; a project script that runs
kicad-cli takes it from `pcbkit.kicad.KICAD_CLI` too, not from `/Applications/KiCad/...`.

## When to use what

| Situation | Command |
| --- | --- |
| Is the schematic legal? | `pcbkit erc boards/x/x.kicad_sch` |
| Does the schematic read well? | `pcbkit sch-lint boards/x/x.kicad_sch` (every sheet below it): texts on top of each other or on another symbol, wires through text, a reference or value far from its part, and small local nets (2 to 4 pins, not leaving the sheet) joined by labels where a wire would show the circuit. `--summary` for the counts per sheet. Then open the sheet in `docs/previews/<board>/schematic.pdf` and look: the check estimates text sizes |
| Generate a sheet that reads | In the sheet script, give the ICs and connectors their x, y and place the parts round them by pin, so the pins that share a net line up: `sch.put(l1, "1", sch.step(sch.pin(u2, "8"), "right", 17.78), toward="right")` puts the inductor in line with the switch pin, `toward="down"` hangs a catch diode or a divider resistor from the row, `sch.chain(point, [f1, q5], toward="right")` sets parts in series (pin positions come from the symbol libraries, before anything is placed). Better, for anything with a main path, describe the block and let `sch.block` place it: first read the circuit and say for each part what it does (in the path, hanging from a node of it, on some other pin, across another part), then `b = sch.block("3.3 V buck", (x, y), path=[(u5, "4", "3"), l2], shunt={"+5V": [c8], "+3V3": [c9, c19, [r8, r9]]}, taps=[(q5, "4", [r21])], across=[(r8, [c25])])`: input on the left, output on the right, parts to GND hang down and parts to a supply up, a list is parts in series (a divider), `b.box` is where it ended up, for placing the next block. Put every part of the sheet in a block (a row can start at a connector, `(j2, None, "2")`; a `PWR_FLAG` hangs from a rail as `(flag, "up")`; `b.add(part)` takes in one you placed by hand; `sense=[(u5, "5")]` has a feedback or sense pin wired to its node elsewhere in the block, round whatever lies between, instead of labelled), then set the page out in rows and build twice, the second time by the measured sizes: `for again in (False, True): sch.arrange([[inp, buck5], [usb, buck3]]); sch.reset(sheet); sch.build(sheet, base, comps, hier, wire=25.4, blocks=B); sch.fields(sheet); sch.measure(sheet, B)` and last `sch.frames(sheet, B)`. `build(blocks=...)` draws each node row as one wire with one name or one power symbol and stops if a rail would cross another net's pin or a part; `fields` sets reference and value level beside each part; `frames` draws the frames `arrange` lined up and names any part left in no block. Then call `build(..., wire=25.4)`: small local nets (2 to 6 pins) are drawn as wires where a straight, L or Z run is clear, named once on the wire; the rest keep a label per pin and the netlist is the same either way. Then `pcbkit sch-lint`: a `label-island` is a part to move next to what it works with, and overlaps between two rows of a block mean a longer `pitch`, another side, or a second block. Render the sheet (`kicad-cli sch export pdf`, then a PNG) and look at it before calling it done |
| Is the schematic what we meant? | run the project's netlist assertions (built on `pcbkit.checks.netlist.Netlist`); `pcbkit nets SCH NET...` to look |
| Is the board clean? | `pcbkit drc BOARD --save` (refills zones and writes the board back; 0 errors, 0 unconnected, 0 parity) |
| Anything DRC can't see? | `pcbkit check BOARD` (floating copper, stubs, loops, thin power feeds, courtyards), `pcbkit cleanup BOARD --dry-run` (after a scripted route: `--dangling` too) |
| Can the courtyards be trusted for placement? (an imported board, a vendor's or a project library's footprints) | `pcbkit courtyards BOARD` or `LIB.pretty`: none, on the other side from the pads, pads or body outside; `--fix` redraws them round pads and body + 0.25 mm; on a board imported from EasyEDA add `--easyeda PCB.json`, or the body is EasyEDA's silk, drawn well off it. Run it before placing parts: DRC's courtyard checks are only as good as the courtyards. A `courtyards_overlap` left after that: measure the gap between the two parts' pads and bodies; under the assembler's minimum (JLC's "Minimum spacing for SMD components", 2026-09: 0.15-0.35 mm chip to chip, 0.2 chip to SOT, 0.4 chip to SOIC and SOT to SOT, 1.0 to a QFN) move one, over it a `.kicad_dru` rule for the two parts with the gap in its name, as for any accepted DRC error (below) |
| Where should this block go? Which output drives which net? | `pcbkit place-score BOARD --study scripts/place_study.py --search --svg out.svg --png out.png`; see the placement-study skill; route only the winner |
| Lay a board's signals again | `pcbkit reroute SETTINGS.json`: its power copper and ground stay, every signal net is routed together, and the result lands beside the board; see the routing skill |
| Route a board by script | a project script under KiCad's Python: `pcbkit.route.complete_nets(board, P, area, plan, track, via, outline=..)` with `plan = [(net regex, [layers], width)]` and `QUICK`, `CONN_SECONDS` and `DEADLINE` in `P` so a run has an end; then `snap_to_pad_centres`, `audit_track_ends`, `pcbkit cleanup --dangling`, `pcbkit drc --save`. Worked example: esp32-s3-ha-node `scripts/route_pcb.py`. Fine-pitch chips (0.4 to 0.65 mm) first get `fanout(board, ref, P, area, track, via, skip_nets=(power and plane nets))`: staggered dog-bone vias out from each signal pad. With only the outer layers for tracks, `P["DIR"] = {F_Cu: "h", B_Cu: "v"}` holds each to one direction (`DIR_COST` along, across, diagonal; default 1, 4, 2) and `P["ORDER"] = "longest"` routes the longest connections first; both are off unless set |
| Review a power stage | `pcbkit netview BOARD out.svg X0 Y0 X1 Y1 --layer B.Cu --png out.png`, then look at the PNG; `--detail` for mask, paste and via holes in paste; to choose between layout options, `--compare` their boards on one sheet (see the visual-review skill) |
| Update the docs' pictures | `pcbkit previews BOARD docs/previews/<board>` |
| Order files | `pcbkit release` (every changed board gets its next version, stamped into it, and its JLC and PCBWay files in its release folder; `--dry-run` first, which says the version and what changed: minor when the netlist or BOM changed, patch when only the layout did; `--major` only when the user says the header pinout, outline, mounting holes or GPIO map changed; a first release whose title block names a version needs `--version`: ask the user whether boards of that version were built, with what the output says git knows, and give the next version if they were and the board changed since; a `mockup` line names the DRC errors that stop it), the version's section in the project's CHANGELOG.md, then an order in `production/orders/<date>-<what>/order.toml` pinning the versions and `pcbkit production`; upload from that order's `upload/`. Panels: `pcbkit panel BOARD build/panels/<board> --style both`. Files without a version: `pcbkit fab BOARD build/fab/<board>` |
| The version and date on the silkscreen | a board text with `${REVISION}` and `${ISSUE_DATE}` (`${ISSUE_DATE} ${REVISION}`), which KiCad fills from the title block `pcbkit release` stamps; never the version typed in, never `v${REVISION}` (prints vv1.0) or `${CURRENT_DATE}` (the day of the plot): release refuses both. `[release] date_format = "%m.%Y"` in pcbkit.toml for 11.2026, `label = "full"` for v1.4.0 instead of v1.4 (docs/CONVENTIONS.md says when) |
| What changed since the last release, for CHANGELOG.md | `pcbkit changelog` drafts it from the boards: the netlist and BOM changes, then the layout's, since each board's last release; `--since archive/<as-built>.kicad_pcb` or a git commit for a board never released (without it, the commit where its title block first read its version); `--all` for each release against the one before. Write the entries with the why, citing DESIGN.md's decisions (D12) and review findings (F27), one section per version as docs/CONVENTIONS.md lays out, and say they were checked against the draft |
| A DRC error that is accepted (a vendor footprint as it was built) | measure it, then a rule in the board's `.kicad_dru` scoped to the part (`A.memberOfFootprint('USBC1')`), its limit just under the measured value, its name and comment saying the part, the value and why; not a DRC exclusion. docs/CONVENTIONS.md, "Checks before an order", has ESP Candle's |
| An earlier version's design, or two versions side by side | `releases/<board>/v<label>/kicad/<board>.kicad_pro` (`{folder}/fab/v<label>/kicad/` in a series): the release's frozen KiCad project, which opens on its own; read only, since release folders are never rewritten. Its MANIFEST.txt lists any 3-D model or library it doesn't find. What changed since a version: `pcbkit changelog BOARD --since releases/<board>/v<label>/kicad/<board>.kicad_pcb`; between each release and the one before, `--all`; any two boards' netlists and BOMs, `pcbkit.release.versions.circuit_changes(circuit(a), circuit(b))` in Python |
| JLC's placement preview, before paying for assembly | the checklist beside the CPL: `PLACEMENT-<board>-v<version>-jlcpcb.md` in the order's `upload/` (`PLACEMENT-<board>.md` from `pcbkit fab`): every part whose orientation matters, its CPL angle, the rotation rule behind it and when that rule was last seen right (**never**: no check on record), and where pad 1 and the centre should read. The fab-order skill goes through it in the viewer and says what to fix in `pcbkit/data/jlc/corrections.csv` |
| What to buy for hand assembly (panel parts, connectors, cables) | the order's ORDER.md, "Parts for hand assembly": its hand parts plus what pcbkit.toml's `[[production.part]]` rules add (`group` to give a connector both a part and a cable, `replace` for a part counted elsewhere, `buy` for where it comes from); after changing the rules, `pcbkit release --refresh-parts`, then `pcbkit production` |
| An order was placed, shipped, arrived or hit a problem (a stock shortage) | add an `[[event]]` to its order.toml (date, status, `pcb` when it is one board, `order_no`, `price`, `note`); boards and parts that arrived go in `production/stock.toml`; then `pcbkit production` and commit, so git has the history |
| Spares or a rework kit to buy with an order, or a board with its own fab settings | `[[extra]]` part, qty, buy, note in its order.toml; a board's own `fab = "..."` (a front panel's black mask); then `pcbkit production` |
| Silkscreen meant to print inside mask openings (numerals in a face panel's windows) | `keep_silk_in_mask = true` in the board's `[[release.profile]]` in pcbkit.toml, so `pcbkit release` keeps it (`pcbkit fab --keep-silk-in-mask` without a version); otherwise the Gerbers lose it. Say so in the order remark too, or the fab house may clip it |
| Start a new project | `pcbkit new ~/Documents/Projects/<name> --board <b> --title "..."`, then write DESIGN.md (requirements, constraints, candidate parts with `pcbkit jlc` stock, decisions) before any schematic |
| Fit a board to an enclosure | measure the box (calipers, or a photo against a ruler), write `boards/<b>/enclosure.json`, then `pcbkit outline boards/<b>/<b>.kicad_pcb boards/<b>/enclosure.json`; record the numbers and their accuracy in LAYOUT.md |
| Bring an EasyEDA design into KiCad | `pcbkit import-easyeda SCH.json PCB.json boards/<b> --name <b> --lib lib --lib-name <project>` (every board of the project into the one library); archive the JSON under `archive/vN-easyeda/`, record findings in DESIGN.md, then `bomi init` + `bomi import kicad` in the board folder. The courtyards KiCad's importer leaves are often wrong: the import draws each body on fab from EasyEDA's component shapes, redraws the courtyards that miss pads or the body and lists them; one larger than the part stays, so look at a netview before placing tight. It also fetches each part's 3-D model from EasyEDA into `lib/3dmodels/` (VRML, placed by EasyEDA's outline of it) and lists any it couldn't fetch or place; `--no-fetch` offline uses only the models already there |
| Which part did we use for this before? | `library/PARTS.md` in this kit; `pcbkit parts TEXT` shows its current stock |
| Find a part quickly | `pcbkit jlc --desc "%...%" --package "0402%" --basic`; for a researched BOM use bomi |
| Does a rail survive a load step, does reset trip? | `pcbkit spice deck.cir --gear-retry`; see the power-sim skill |
| Is it ready to order? What could fail once it's built? Where do test points go? | the failure-review skill: references, failure modes, tests, a briefing in `docs/reviews/`; no edits until the user has read it |

Related skills in this kit: **visual-review** (which picture answers which question), **power-sim** (ngspice),
**bom-cost** (bomi, stock, Extended fees), **enclosure-fit** (box to outline to paper test), **placement-study**
(score placements by their ratsnest, route only the winner), **routing** (`pcbkit reroute`: a board's signals laid again),
**failure-review** (what could fail after fab, how
we'd find it, test points), **fab-order** (the JLC and LCSC carts in the browser: options, BOM page, placement
viewer, quotes).

## Rules

- Read the project's README, DESIGN.md and LAYOUT.md first; the status line at the top of each says where things stand.
- Never regenerate a routed board from scratch. Incremental edits only, keeping UUIDs.
- Locked copper is deliberate. Leave it.
- After any copper edit: `pcbkit cleanup`, `pcbkit drc --save`, `pcbkit check`, in that order.
- Before an order, follow the checklist in `docs/CONVENTIONS.md` of this kit and the project's PRODUCTION.md.
- Project-specific data (placement tables, net lists, power-stage geometry) belongs in the project, not in the kit.
  If you find yourself adding a board's names to the kit, stop and put them in the project.
- KiCad Python gotchas: `BOARD.Remove()` on tracks corrupts the bindings mid-run (edit the file text by uuid);
  `FOOTPRINT.Remove(item)` hands the item to Python, which frees it under the board's caches and pcbnew starts
  returning untyped objects a few footprints later (set `item.thisown = False` after it);
  `pcbnew.SaveBoard` aborts headless (use `PCB_IO_MGR.Save`); a `.kicad_dru` syntax error disables all custom rules.
